# /screenshot-review — ビジュアルリグレッション確認

CLAUDE.md 記載の「スクショ駆動ビジュアル確認」ワークフローを実行するスキルです。
配色変更・UI 統一・レイアウト変更後の取りこぼし検出に特化しています。

---

## 前提

- ローカル dev サーバーが起動していること（`npm run dev`）
- スクリーンショットはまだ撮影されていない（または最新化したい）

---

## 手順

### 1. スクショ撮影

ユーザーに以下を実行してもらう（または Bash で実行する）：

```bash
npm run screenshot
```

- 出力先：`screenshots/YYYY-MM-DD/` に全アプリ分の PNG が生成される
- viewport: 1024×768（タブレットファースト）

撮影完了を確認してから次のステップへ。

---

### 2. 優先確認リストを決める

直近の git diff から「変更が大きかったアプリ」を特定する：

```bash
git diff --name-only HEAD~1 HEAD
```

または今回の変更範囲をユーザーに確認する。

**確認の優先順位（高→低）：**
1. トップページ（`00_index.png`）— 全体トーンの基準
2. 変更が大きかったアプリ（ハンクが多い順）
3. 共通部品（Header/Footer）を多く使うアプリ
4. インライン書きが多いアプリ（筆算・タイマー系）

---

### 3. 最新 screenshots フォルダを特定

```bash
# 最新日付フォルダを確認
ls screenshots/
```

最新の `YYYY-MM-DD/` フォルダ内の PNG を Read ツールで読み込む。

---

### 4. 画像を目視チェック

以下の観点で確認する：

| 観点 | チェック内容 |
|------|------------|
| カラートーン | 他アプリと比べて色が浮いていないか |
| ボタン配色 | brand/accent/warm トークンに沿っているか（生の red/blue/green が混ざっていないか） |
| レイアウト | 要素がはみ出していないか・重なっていないか |
| ダークモード | 対応している場合、背景/テキストが読めるか |
| フォント | 文字が正しく表示されているか |

**1 枚ずつ Read して確認する。全 59 枚は読まず、優先リストに絞る。**

---

### 5. 問題発見 → 修正

崩れや色味の違和感を発見した場合：

1. 該当ファイルを `Grep` で特定（raw カラー・インライン style など）
2. `Edit` で修正
3. 修正後、該当アプリのスクショを再撮影して確認

```bash
# 特定アプリだけ再撮影したい場合
BASE_URL=http://localhost:3000 npm run screenshot
# → 全アプリ再撮影になるが、気になるアプリを Read で再確認する
```

---

### 6. 完了報告

```
## screenshot-review 結果

確認枚数: N 枚
問題あり: X 件 → 修正済み
問題なし: Y 枚

### 修正した箇所
- src/app/(apps)/xxx/page.tsx: bg-red-500 → bg-brand-500 に修正
- ...
```

---

## よくある取りこぼしパターン

- `bg-red-500`、`bg-blue-500`、`bg-green-500` などの生カラー（トークン未使用）
- `text-red-600`（エラー文言以外での生カラー）
- ダークモード対応漏れ（`dark:` プレフィックスなし）
- ホバー色が通常時と同じになっている（`hover:` 指定漏れ）
