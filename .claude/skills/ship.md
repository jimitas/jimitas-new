# /ship — 開発まとめ & Push

開発が一段落したときに実行するスキルです。
以下を順番に行います。

## 手順

### 1. テスト実行
```bash
npm test
```
失敗したら原因を調べて修正してからコミットに進む。

### 2. 変更内容の確認
```bash
git status
git diff
git log --oneline -5
```
未コミットの変更・ステージ状況・直近コミット履歴を確認する。

### 3. git add → commit → push
- `docs/` 内のスクリーンショット（`image.png` など一時画像）はコミットに含めない
- コミットメッセージは変更内容に基づいて日本語で生成する（`feat:` / `fix:` / `perf:` などのプレフィックスを使う）
- `Co-Authored-By: Claude Sonnet 4.6 (1M context) <noreply@anthropic.com>` を末尾に付ける
- push 前フックがテストを自動実行するので、その結果も確認する

### 4. Claude Web 向け報告レポートを作成して提示

以下の形式でレポートを作成する。

---

## Claude Web 向け報告レポート

**日時：** YYYY-MM-DD
**コミット：** `ハッシュ7桁`

### 今回やったこと：〈一言タイトル〉

#### 背景・目的
なぜこの変更をしたか。ユーザーの課題・要望を簡潔に書く。

#### 変更内容
箇条書きまたは表で変更点をまとめる。
技術的な実装の詳細よりも「何が変わったか・なぜそうしたか」を重視する。

#### 技術的なポイント（あれば）
実装上の工夫・トレードオフ・注意点があれば書く。

---

## 注意事項

- テストが失敗した場合はコミットせず、先に修正する
- `docs/image.png` のような一時ファイルはコミットしない（`.gitignore` で管理）
- push 後にレポートを提示する（push 前ではなく後）
