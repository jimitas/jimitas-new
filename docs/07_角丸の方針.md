# 角丸（border-radius）の方針

**作成: 2026-09-13 / 状態: 決定済み（2026-09-13）**

## 決定（先に結論）

| 用途 | 角丸 | 例 |
|---|---|---|
| **汎用の操作ボタン** | **8px（`rounded-lg`）** | もんだい / こたえあわせ / スタート |
| **内容カード**（絵文字＋語を選ばせるもの） | **12px（`rounded-xl`）** | katakana / romaji / english-words の選択肢 |
| **小さい操作**（高さ 24px 以下の目安） | **4px（`rounded`）** | 大/中/小/極小 のサイズ切替 |
| 色スウォッチ | 6px（`BtnColor` 専用） | masu-nuri |
| 表のマス目 | 0px | kuku-hyo の九九表 |
| モード切替のピル・大タイル | full / 16px | kenban / dagakki |

**「1つに統一」ではなく「用途ごとに決める」形を採った。**
実測すると揺れているのではなく用途ごとの塊だったため、
実態に名前を付けるほうが正しいと判断した（経緯は下記）。

新しくボタンを作るときは、まず共通部品（`Btn`）を使う。
`Btn` は 8px なので、汎用の操作ボタンなら何も考えなくてよい。

---

## 以下、判断の材料（測定結果）

ボタン集約 段階3（手書きボタンを共通部品へ移行）に入る前に、
「角丸の house style をどれにするか」を決める必要がある。
その判断材料をここにまとめる。

---

## 1. 前提の訂正：「三つ巴」ではなかった

段階1の報告には次のように書いた。

> 現状 `rounded-lg` 148件 / `rounded-xl` 138件 / `rounded-full` 39件で三つ巴

これは**ソースコードの文字列を数えたもの**で、実態とずれている。
パネル・カード・入力欄など、ボタン以外の角丸が混ざっているためである。

そこで **実際に画面に出ているボタンを測り直した**（61アプリ・タブレット幅・初期表示）。

| 区分 | 個数 |
|---|---|
| 背景色のある「ボタンらしいボタン」 | **670個** |
| 透明な包みボタン（画像やセルを包むだけ） | 29個（対象外） |

### 実測した分布（670個）

| 角丸 | 個数 | 割合 |
|---|---|---|
| **8px**（`rounded-lg`） | **286** | **42.7%** |
| 12px（`rounded-xl`） | 193 | 28.8% |
| 0px（角丸なし） | 101 | 15.1% |
| 4px（`rounded`） | 56 | 8.4% |
| 6px（`rounded-md`） | 18 | 2.7% |
| full（完全な丸） | 12 | 1.8% |
| 16px（`rounded-2xl`） | 4 | 0.6% |

---

## 2. 数字の内訳を見ると、ほとんどが「用途ごとの塊」だった

バラバラに散っているのではなく、**まとまって特定のアプリ・特定の用途に属している**。

| 角丸 | 正体 | 主なアプリ |
|---|---|---|
| **8px** | 汎用の操作ボタン。**共通部品 `Btn.tsx` の値** | 全体に分散 |
| 12px | 絵文字＋語のカード型ボタン | katakana(86) / romaji(36) / english-words(32) |
| 0px | 九九表のマス目（表なので角丸なしが正しい） | kuku-hyo(100) |
| 4px | 30×22 程度の小さいサイズ切替（大/中/小/極小） | kuku-array / 筆算4本 / sansu-note |
| 6px | 色スウォッチ（`BtnColor` の値） | masu-nuri / kuku-hyo |
| 16px | 大きな楽器タイル（235×196） | dagakki |
| full | モード切替のピル | kenban / gakuten / oto-dashiyo ほか |

### 共通部品はすでに揃っている

| 部品 | 角丸 |
|---|---|
| `Btn.tsx`（名前付き8部品の土台）・`BtnConfirm`・`BtnMode`・`BtnNum` | `rounded-lg`（8px） |
| `BtnColor` | `rounded-md`（6px・色スウォッチ専用） |
| `NumPad` | 枠が `rounded-2xl`、キーは `rounded-lg` |

**共通レイヤーは実質 8px で統一済み。** 揺れているのは手書き側だけ。

---

## 3. 同じ画面に複数の角丸が同居しているか

55アプリ中 **22アプリ**で2種類以上が同居する。ただし多くは
「操作ボタン 8px ＋ 内容カード 12px」のように**役割が違う**組み合わせ。

役割が同じなのに揺れている例は少ない。

| アプリ | 同居している角丸 |
|---|---|
| kuku-hyo | 6px / 8px / 0px |
| kuku-array | 4px / 8px |
| kazoe-bou | 8px / 4px |
| fushi-dukuri | 4px / 8px |
| masu-nuri | 8px / 6px |

---

## 4. 決めたこと と その理由

### 論点A：汎用の操作ボタンの house style → **8px に決定**

理由は3つ。

- すでに最多（42.7%）
- **共通部品の現在値と一致**するので、段階3の移行で見た目が変わる箇所が最小になる
- 12px・0px・4px は「用途が違う塊」であり、汎用ボタンの競合ではない

12px を選ぶと、286個を変えたうえで共通部品も変えることになり、
段階3が「部品に寄せる作業」ではなく「全アプリの見た目を変える作業」になる。

### 論点B：カード型ボタン（12px・193個） → **B-1（2段構え）に決定**

katakana / romaji / english-words の「🍒 さくらんぼ」のような、
**絵文字＋語を並べた選択カード**。操作ボタンとは役割が違う。

| 案 | 内容 | コスト |
|---|---|---|
| B-1 | **2段構えとして認める**（操作ボタン=8px / 内容カード=12px） | ゼロ。ドキュメントに書くだけ |
| B-2 | 8px に統一する | 3アプリの見た目が変わる |

**B-1 を採用。** 実際に役割が違い、現状それで破綻していない。
「揺れ」ではなく「使い分け」として明文化するほうが実態に合う。

### 論点C：小さい操作（4px・56個） → **C-1（4px を許容）に決定**

「大/中/小/極小」のような 30×22 程度のボタン。
8px を当てると、小さいボタンでは角丸が相対的に大きく見える。

| 案 | 内容 |
|---|---|
| C-1 | **小さいボタンは 4px を許容**（高さ 24px 以下など基準を決める） |
| C-2 | 8px に統一する |

**C-1 を採用。**「小さい」の目安は **高さ 24px 以下**とする
（実測で該当する 30×22 のサイズ切替ボタンが収まり、
通常の操作ボタン 40〜52px とは明確に分かれる）。

境目のボタンが出てきたら 8px 側に寄せる。例外は増やさない。

### 触らないもの

- **0px（kuku-hyo の九九表）** — 表のマス目。角丸なしが正しい
- **6px（BtnColor の色スウォッチ）** — 専用部品ですでに統一されている
- **full / 16px** — 数が少なく、いずれも意図が明確（ピル・大タイル）

---

## 5. 段階3への引き継ぎ

手書きのボタンを共通部品（`Btn`）に寄せていく作業。
8px を選んだので、**移行の大半は見た目が変わらない**。
`npm run layout-compare` で「差分ゼロ」を要求しながら進められる。

移行の対象・非対象は次のとおり。

| 対象 | 扱い |
|---|---|
| 8px の汎用ボタン 286個 | **`Btn` へ移行する**（見た目は変わらない想定） |
| 12px のカード 193個 | 移行しない（別カテゴリとして据え置き） |
| 0px の九九表 100個 | 移行しない（表のマス目） |
| 4px の小さい切替 56個 | 移行しない（高さ24px以下の例外） |
| 6px / full / 16px 34個 | 移行しない（専用部品・意図が明確） |

**つまり段階3の実対象は 286個**で、当初の「205個」より多いが、
そのすべてが「見た目を変えずに部品へ寄せる」種類の作業になる。

再測定は `npx tsx scripts/radius-survey.ts`（要 dev サーバー）。
