## 1. 目的

ハノイの塔を**自分で動かし**、**自動で解く様子を見て**、最少回数が **2ⁿ − 1 回**になる理由を、数列・漸化式・数学的帰納法を使わずに（数学Ⅰ・A の範囲で）納得させる。

1. 1枚、2枚、3枚…と実際に解き、回数 1, 3, 7, 15 を記録する。
2. 「回数に 1 を足すと 2, 4, 8, 16 → 2 を n 回かけた数」と気づき、5枚は 31 回と予想して確かめる。
3. 「n 枚の回数 ＝（n−1 枚の回数）＋ 1 ＋（n−1 枚の回数）」という**しくみ**を、自動アニメーションの色分けで目で見る。
4. 円盤ごとに動いた回数を数えると 1, 2, 4, 8, … になり、合計は **2進法で 1 が n 個並んだ数 ＝ 2ⁿ − 1**（数学A「記数法」とつながる）。
5. 64枚なら何年かかるかを計算し、「世界の終わり」はずっと先であることを確かめる。

### 1.2 用語・表記の方針（教科書にそろえる）

- 棒は **A, B, C**。最初はすべて A。移動先は **B または C**（教科書の2枚の例は B、3枚の例は C）。初期値は C、B に切り替え可。
- 「円盤」（教科書は「円板」だが、ビデオの語りに合わせて「円盤」で統一）【要確認 Q6】
- 円盤には小さい順に **①②③…** の番号を付ける（色だけに頼らない）。
- 「漸化式」「数学的帰納法」「等比数列」「再帰」の語は「ことばで」表示では使わない。「記号で」表示とステップ⑤の補足でのみ使う。
- 画面の語り口は「〜してみよう」「〜になっているね」。先生の一人称を使う場合は「わたし」。

## 3. 画面構成

1ページ内に5つのステップ（タブ）。初期表示は①。

```
[ ① あそぶ ] [ ② 自動で解く ] [ ③ 回数のひみつ ] [ ④ 64枚だと？ ] [ ⑤ 歴史と解き方 ]
```

- ヘッダー付近に常時：**「ことばで／記号で」切替**（初期は「ことばで」）、**「大きく表示」切替**（録画・投影用）。微分アプリと同じ部品・同じ位置。
- 円盤の枚数 n はタブ間で共有（①で 4 枚にしたら ②も 4 枚）。

### 3.1 配色（CUD 準拠）

- 円盤は**枚数ごとに固定の色**（①はいつも同じ色）。基準は授業で作った紙粘土の円盤（2026-11-08 差しかえ）。
  - ①〜⑥：紙粘土の色。色コードはあとで渡される。定数1か所（`_lib/colors.ts` の `CLAY_COLORS`）で差しかえられるようにする。それまでは仮の6色（①赤 ②オレンジ ③黄 ④緑 ⑤青 ⑥紫）【要確認 Q1】。
  - ⑦〜⑩：茶系（木の色）のグラデーション。⑦明るいベージュ → ⑩こげ茶。大きい円盤ほど濃く。
  - 円盤には必ず番号を入れる。番号の文字色は円盤の明るさで白／黒を自動で切りかえる。輪郭線は濃いグレー 1.5px。
  - 台と棒はグレー（茶色の円盤とまぎれないように）。
- **色の意味は「円盤の色＝その円盤が動く」の1つだけ**。ボタン・強調・グラフには円盤と同じ色をなるべく使わず中立色を使う。
- jimitas 既存の配色定数（`docs/06_配色設計.md`）があればそれを優先して役割を当てはめる。
- ステップ②の3つの区切りの色（F2-5）：前半＝濃いグレーの斜線、後半＝薄いグレー、中央の1手＝そのとき動く円盤の色。入れ子表示（F2-6）でも同じ規則。ラベルでも区別する。

## 5. 計算・描画仕様

### 5.1 最少手順の作り方（純TS・jest でテスト）

- `solve(n, from, to, via): Move[]` を再帰で作る（`Move = { disk: number; from: Peg; to: Peg }`、disk は 1＝いちばん小さい）。
  - n 枚を from→to：n−1 枚を from→via、円盤 n を from→to、n−1 枚を via→to。
- n ≤ 10（1023手）なので、手順は先に全部作って配列に持ち、k 手目の状態は「0手目の状態から k 手ぶん適用」で作る（`/algorithm` の recorder と同じ考え方）。スライダーでの移動がもたつく場合は、状態のスナップショットを 64 手ごとに持つ。
- 3つの区切り（F2-5）：k 手目が前半（1〜2ⁿ⁻¹−1）／中央（2ⁿ⁻¹）／後半（2ⁿ⁻¹+1〜2ⁿ−1）のどれかは k から計算。入れ子（F2-6）も同じ式を再帰的に使う。
- 2進法（F2-8）：k 手目に動く円盤の番号 ＝（k を2進法で書いたとき、右から何けた目に初めて 1 があるか）。最少手順の配列の `disk` と一致することをテストで確かめる。
- 移動先 B のとき、via と to を入れかえるだけ。

### 5.2 大きな数（ステップ④）

- 2ⁿ−1 は `BigInt`（`(1n << BigInt(n)) - 1n`）。
- 年数は `Number(回数) × 秒 ÷ 31,557,600`（有効数字3〜4けたで十分なので、ここだけ Number に変換してよい）。
- 日本語の単位（万・億・兆・京）への変換関数を作り、テストする（2⁶⁴−1 → 「1844京6744兆737億955万1615」）。
- 表示例：64枚・1回1秒 → 「約5845億年（宇宙の年齢 約138億年の 約42倍）」。

### 5.3 歴史・伝説の記述に使う事実（これ以外は書かない）

- 1883年、フランスの数学者 **エドゥアール・リュカ**（Édouard Lucas）が、パズル（おもちゃ）として発表した。
- そのときの作者名は「N. クラウス・ド・シャム教授（N. Claus de Siam）」。これは「リュカ・ダミアン（Lucas d'Amiens＝アミアン出身のリュカ）」の文字を並べかえたもの（アナグラム）。
- 当時の売り出し文句として「インドのベナレス（いまのバラナシ）の大寺院に、64枚の金の円盤がダイヤモンドの針に積まれており、僧たちが昼も夜も規則どおりに移しかえている。全部移し終えたとき、塔も寺院も崩れて世界は終わる」という伝説がつけられた。**この伝説はリュカの創作と考えられている**。
- 「ハノイ」はベトナムの都市の名前。当時フランスがインドシナ（いまのベトナムなど）に進出していたことが名前の由来と考えられている。
- リュカが売り出した元のおもちゃは円盤 8 枚。
- リュカはフィボナッチ数列の研究でも知られる（「リュカ数」）。※数学Ⅰの鴨川ビデオでフィボナッチ数を扱っているので、ひと言つなげてよい。

### 5.4 描画

- SVG を React で直接描画（微分・積分アプリと同じ）。円盤の幅は枚数に応じて自動で決め、10枚でも重ならず読めること。
- 円盤の移動アニメーションは requestAnimationFrame、60fps 目安。速さ 0.02秒/手のときは弧の動きを省いて瞬間移動でよい。

## 8. 受け入れ基準

1. ステップ①：n＝3 で、最少手順どおり 7 回でクリアすると「最少回数でクリア！」。ルール違反の移動は回数に数えられない。最少回数は初期状態で表示されていない。
2. ステップ②：n＝4 で最後まで再生すると 15 手で終わり、3つの区切りのバーに「7 ＋ 1 ＋ 7 ＝ 15」、円盤ごとの回数表が ④1・③2・②4・①8 になる。
3. ステップ②：進み具合スライダーで任意の手に移ったときの状態が、1手ずつ進めた状態と一致する。
4. ステップ③：表の「回数＋1」が 2, 4, 8, 16, 32 … となり、n＝5 の予想ボタンで 31 が出る。ブロック図で [3][1][3][1] が [4][4] に組み直される。
5. ステップ④：64枚で 18,446,744,073,709,551,615 回、「1844京6744兆737億955万1615 回」、1回1秒で約5845億年、宇宙の年齢の約42倍と表示される。
6. ユニットテスト：`solve(n)` の手の数が 2ⁿ−1（n＝1〜10）、全部の手がルールを守り、最後に全円盤が移動先にある。円盤 j の移動回数が 2ⁿ⁻ʲ。2進法のルールで求めた円盤番号が手順と一致する。日本語単位の変換。
7. `/algorithm`・`/bibun`・`/sekibun-en` の既存テストがすべて通り、表示も変わっていない。
8. `next build` が警告なく通る。
