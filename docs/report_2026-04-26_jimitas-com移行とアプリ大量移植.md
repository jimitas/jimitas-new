## 背景

これまでの jimitas プロジェクトは:
- 本家 `jimitas.com` = WordPress（さくら）でブログ的に各アプリを紹介
- 個別アプリ = Vercel/Netlify でバラバラにホスティング
- 新統合プロジェクト `jimitas-new` = jimitas-new.vercel.app でほぼ完成

「jimitas-new を本番にしたい・WordPress の管理コスト（さくら契約）を払いたくない」という動機で、
**jimitas.com のドメインを Vercel の jimitas-new に向ける** 大移行を実施。

## Part 1: 移行戦略の検討

### 判断ポイント

| 論点 | 結論 |
|------|------|
| ブログ自体は残すか？ | **残さない**（管理コスト・WordPress 不要） |
| SEO はどうする？ | 「jimitas」指名検索で新サイトが出れば十分 |
| 旧サイト訪問者への配慮は？ | 旧URL→新URLのリダイレクトで対応 |
| 個別ホスティング（Vercel/Netlify）は？ | 急に消さない・緩やかに誘導 |
| TV取材（授業準備TV）との兼ね合い | UIで見つけやすければ問題なし |

### 採用した方針

**ブリッジバナー案（緩やかなリダイレクト）**: 旧URLを踏んだ訪問者には
> 「現在、jimitas.com にアプリを集約しています。そちらへの移行をお願いします。（将来このページは削除予定です）」

をバナー表示。**強制リダイレクトはしない**ことで、ブックマーク利用者を驚かせない配慮。

### 「自慢っぽいバナーは作らない」

「TVで紹介されました！」のような自己宣伝バナー案 → **却下**。
「地味に助かる」という哲学に反する。控えめに、機能で勝負する。

## Part 2: DNS 切り替え + リダイレクト整備

### 実施内容

1. Vercel 管理画面で `jimitas.com` をカスタムドメインに追加
2. さくらのドメイン側で DNS を Vercel に向ける
3. `next.config.ts` の `redirects()` で旧静的HTMLパス → 新ルートへリダイレクト
4. `app/sitemap.ts` で全ルートを自動列挙（[printId] 動的ルート対応）
5. `public/robots.txt` で sitemap を宣言

### コミット

```
5d73345 chore(migration): jimitas.com 移行準備（リダイレクト・メタデータ・移行マップ）
68259fb feat(seo): sitemap.ts に [printId] 動的ルートを追加
07b3d62 feat(redirects): さくらサーバー上の静的HTMLパスのリダイレクトを追加
```

### マッピング詳細

旧 `jimitas.com/kanji/` → 新 `jimitas.com/kanji-test`
旧 `*.vercel.app` / `*.netlify.app` → 新 `jimitas.com/<対応ID>`

詳細は [05_jimitas_com_migration_map.md](./05_jimitas_com_migration_map.md) 参照。

### BtnConfirm 共通部品の誕生

途中で「アラートの代わりに埋め込みで『はい』『いいえ』を聞く部分が散らばっている」ことに気づき、
共通部品として `BtnConfirm` を作成（ec546e3）。

これにより、5アプリのインライン確認が統一された。
**confirm()/prompt()/alert() を使わない**というプロジェクト方針が部品レベルで強化された。

## つまずきと学び

### 1. ドメイン移行の説明難易度
「jimitas.com/kanji/ を踏んだ人が新サイトに飛ぶ」という設定、初心者には**難しい**。
- 「リダイレクトはどこに置く？」（旧サイト or 新サイト）
- 「sangenshoku.vercel.app をブックマークしている人は？」
- 「ステップごとに丁寧に」と要望 → 計画を1つずつ確認しながら進めた。

### 2. 案を矢継ぎ早に出すと混乱する
ユーザーから「claude codeの回答が追いついていない、計画をわかりやすく説明して」との指摘。
**1つずつ完了確認しながら進める** ことが大事だった。

### 3. ブックマーク利用者への配慮
個別ホスティング（Vercel/Netlify）を**急に削除しない**。
緩やかなバナー表示で誘導しつつ、自然に移行してもらう。

### 4. なんでもトランプ・絵あわせは画像が原因
シークレットモードで動いた → ブラウザキャッシュ問題。
さらに `next/image fill` が動かず通常の `<img>` タグに変更（9c0d111）。

### 5. ふしづくりの大改造は教育的価値ありき
「ドラッグ&ドロップで音符配置」は単なる UX 改善ではなく、
**「楽譜の音符をちゃんと理解させたい」** という教育目的に基づく設計。
シーケンサー風だけど、音符は楽典通り。これは記録に残す価値があった。
