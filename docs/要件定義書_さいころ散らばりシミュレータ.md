# 要件定義書：さいころの散らばりシミュレータ（仮称）
### jimitas.com 追加コンテンツ／数学Ⅰ「データの分析」

---

## 1. 背景

数学Ⅰ後期スクーリング「平均が同じなら、同じデータ？」では、班ごとにA方式・B方式でさいころを **10回** 振り、平均・分散・標準偏差を手計算する。理論上の標準偏差はA方式が約2.4、B方式が約3.4で、A方式のほうが散らばりが小さい。

しかし **試行10回は少なすぎて、実測値が理論値から大きくズレる**。授業中に「A方式の班のほうが標準偏差が大きい」という逆転が起こりうる。これは失敗ではなく「データが少ないとブレる」という統計の本質そのものだが、**口頭説明だけでは生徒が納得しにくい**。

このアプリは、その場で試行回数を増やして確かめられるようにし、さらに「10回のセットを何度も繰り返すと、標準偏差はどれくらいブレるのか」を目に見える形で示す。

## 2. 目的

| # | 目的 |
|---|---|
| 1 | 試行回数を増やすと、分布の形と標準偏差が理論値に近づくことを体験させる |
| 2 | **10回という試行回数では標準偏差がどの程度ブレるのかを定量的に示す**（本アプリの中核） |
| 3 | 授業で自分の班が出した実測値が、そのブレの中でどの位置にあるかを確認させる |
| 4 | 授業後の復習・欠席者のフォロー教材として単独で成立させる |

## 3. 利用シーン

| シーン | 利用者 | 想定 |
|---|---|---|
| 授業終盤（45〜50分） | 教員 | プロジェクタに投影し、全体に見せながら操作する |
| 授業後の復習 | 生徒 | スマートフォンで自分のペースで触る |
| 授業前の確認 | 教員 | その年の班構成でどんな結果が出やすいか事前に把握する |

**最優先はプロジェクタ投影。** 遠くの席から数字が読めることを最低条件とする。

## 4. 機能要件

### F-1　方式の選択

- A方式（さいころ2個の**合計**）／ B方式（さいころ1個の目を**2倍**）をタブで切り替える
- どちらも得点の範囲は 2〜12
- 両方を同時に表示する比較モードを持つ（F-5）

### F-2　試行の実行

- 試行回数を選ぶ：**10 / 50 / 100 / 1,000 / 10,000回**
- 「もう10回ふる」ボタンで、現在の結果に10回ずつ追加できる（授業の実感に合わせる）
- 「はじめから」で全リセット
- 1,000回以上はアニメーションなしで即時計算してよい。10回・50回は1回ずつ積み上がるアニメーション（1回あたり50〜100ms程度）を推奨

### F-3　ドットプロット表示

- 横軸は 2〜12 の整数（11列固定）。**授業で使う模造紙と同じ軸**にすること
- 1回の試行を1つの点として縦に積む
- 点が画面に収まらない場合はヒストグラム（棒）に自動で切り替える。閾値は100回を目安
- 平均の位置に縦の破線を引く
- A方式はオレンジ、B方式はブルー（CUD準拠。授業の掲示物・スライドと同じ配色）

### F-4　統計量の表示

常時、次を大きく表示する。

| 項目 | 表示 |
|---|---|
| 試行回数 | n = ○○ |
| 平均 | 実測値（小数第2位）／ 理論値 7 |
| 分散 | 実測値 ／ 理論値（A: 5.83、B: 11.67） |
| 標準偏差 | 実測値 ／ 理論値（A: 2.42、B: 3.42） |

- 実測値と理論値を**必ず並べて**表示する。どれだけズレているかが一目で分かることが重要
- あわせて **横軸＝試行回数・縦軸＝標準偏差の折れ線グラフ**を置き、理論値の水平線に収束していく様子をライブで見せる

### F-5　A方式・B方式の同時比較

- 2つのドットプロットを左右（スマホでは上下）に並べ、同じ試行回数で同時に振る
- 平均はどちらも7に近づき、標準偏差だけが違っていくことを見せる

### F-6　★ 10回セットの繰り返し（本アプリの中核機能）

**「10回ふって標準偏差を出す」を1セットとし、それを多数回くりかえしたときの標準偏差の分布を表示する。**

- セット数を選ぶ：100 / 1,000 / 10,000セット
- 各セットで得られた標準偏差をヒストグラムとして表示する
- 理論値（A: 2.42 / B: 3.42）の位置に縦線を引く
- ヒストグラム上に「このくらいの値が出ることは珍しくない」範囲（中央80%など）を帯で示す
- **授業で自分の班が出した標準偏差を入力すると、その位置にマーカーが立つ**（F-7と連動）

この画面が答えるべき問いは次の1つに尽きる。

> 「10回しか振っていない自分たちの標準偏差は、理論値とズレていて当たり前なのか？」

ヒストグラムの幅が広いこと自体が答えになるよう、縦線・帯・マーカーで視覚的に読み取れる形にする。

### F-7　実測データの入力

- 授業で班が記録した**10個の得点**を手入力できる（入力欄10個、またはカンマ区切り1行）
- 入力すると、その班のドットプロット・平均・偏差・分散・標準偏差を表示する
- 偏差の一覧と **偏差の合計（必ず0になる）** を表示し、生徒の手計算の検算に使えるようにする
- F-6のヒストグラム上に、そのデータの標準偏差の位置をマーカー表示する
- バリデーション：A方式は2〜12の整数、B方式は2〜12の偶数

### F-8　再現性（任意・優先度低）

- 乱数シードを指定できると授業で同じ結果を再現できて便利。実装コストが低ければ入れる
- 入れない場合も、スクリーンショットが撮れれば実用上は足りる

## 5. 画面構成

縦スクロール1ページ構成。ページ内リンクで各セクションに飛べるようにする。

```
┌─ ヘッダー：タイトル／ひとこと説明
├─ セクション1：ふってみる                  （F-1, F-2, F-3, F-4）
│    方式タブ ／ 回数ボタン ／ ドットプロット ／ 統計量カード
│    ＋ 標準偏差の収束グラフ
├─ セクション2：A方式とB方式をくらべる        （F-5）
├─ セクション3：10回だと、どれくらいブレる？  （F-6）★中核
│    セット数ボタン ／ 標準偏差のヒストグラム ／ 理論値の線
├─ セクション4：自分の班のデータを入れてみる  （F-7）
│    10個の入力欄 ／ 偏差一覧 ／ 偏差の合計=0 ／ ヒストグラム上のマーカー
└─ フッター：用語のおさらい（偏差・分散・標準偏差の定義）
```

授業ではセクション1 → 3 の順で使う。セクション2・4は生徒が後から触る想定。

## 6. 計算仕様

実装時にブレやすい箇所なので、ここは厳密に従うこと。

### 母集団の定義

| 方式 | 得点 | 確率 |
|---|---|---|
| A方式 | 2個のさいころの和（2〜12） | 2個の独立な一様分布の和 |
| B方式 | 1個のさいころの目 × 2（2,4,6,8,10,12） | 各 1/6 の一様分布 |

### 理論値

| 方式 | 平均 | 分散 | 標準偏差 |
|---|---|---|---|
| A方式 | 7 | 35/6 = 5.8333… | 2.4152… |
| B方式 | 7 | 35/3 = 11.6667… | 3.4157… |

B方式の分散はA方式のちょうど2倍。この関係が崩れていたら実装ミス。

### 分散の定義（重要）

**偏差の2乗の和を n で割る（記述統計の分散）。** n−1 で割る不偏分散は**使わない**。授業で生徒が手計算する式と一致させる必要がある。F-6で各セットの標準偏差を求めるときも同様に n（=10）で割る。

> 注：n で割った標準偏差は母標準偏差をやや小さめに見積もる性質があるため、F-6のヒストグラムの山は理論値の線よりわずかに左に寄る。これは不具合ではない。気になる場合は「10回で計算した標準偏差の平均」の線も引き、理論値の線と区別して示すとよい。

### 表示桁

- 平均・分散・標準偏差：小数第2位まで（四捨五入）
- 偏差：小数第1位まで（授業の手計算と同じ桁にそろえる）

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応環境 | スマートフォン（縦）／タブレット／PC。プロジェクタ投影（1280×720以上）で数字が読めること |
| 配色 | CUD準拠。A方式＝オレンジ、B方式＝ブルー。赤は使わない。授業スライド・掲示物と同じ配色にそろえる |
| フォント | サイト既存の設定に準拠 |
| ログイン | 不要。個人情報は一切扱わない |
| 通信 | 初回ロード後はサーバ通信なし。乱数生成・集計はすべてクライアント側 |
| レンダリング | SSG。インタラクション部分のみクライアントコンポーネント |
| パフォーマンス | 10,000回の試行、10,000セットの繰り返しが1秒以内に完了すること。必要なら計算をチャンクに分けてUIをブロックしない |
| アクセシビリティ | 色だけで方式を区別しない（ラベルを必ず併記）。数値はテキストとしても読めること |

## 8. 文言の方針

- 対象は高校生。予備知識なしを前提とする
- 「標本」「母集団」「不偏」などの用語は画面に出さない
- 「理論的には」「10回だとブレます」といった授業で使った言い回しをそのまま使う
- セクション3の見出しは問いの形にする（例：「10回だと、どれくらいブレる？」）

---

## 9. スコープ外

- 正規分布・中心極限定理の説明（山の形が現れることは見せるが、名前は出さない）
- 偏差値の計算（読み物資料で扱うため、アプリには入れない）
- データの保存・共有・印刷
- A方式・B方式以外の試行方式（カード方式などは将来の拡張）
- 四分位数・箱ひげ図

---

## 10. 受け入れ条件

| # | 条件 |
|---|---|
| 1 | A方式で10,000回ふると、平均が 7.0±0.1、標準偏差が 2.42±0.05 に収まる |
| 2 | 同条件でB方式の分散がA方式の約2倍（1.9〜2.1倍）になる |
| 3 | B方式の出目に奇数が1つも含まれない |
| 4 | ドットプロットの横軸が2〜12の11列で固定され、試行回数を変えても軸が動かない |
| 5 | F-7に10個の得点を入力したとき、偏差の合計が必ず 0.0 と表示される |
| 6 | F-6で10回×1,000セットを実行したとき、標準偏差のヒストグラムが明確な幅を持って広がる（1点に集中しない） |
| 7 | スマートフォン縦画面で横スクロールが発生しない |
| 8 | 1280×720の投影で、統計量の数値が教室後方から読める大きさである |

## 11. 開発ステップ

Claude Codeでの実装順。各ステップで動く状態にしてから次へ進む。

1. ページの骨組みとセクション分け、方式タブ
2. 乱数生成と統計量の計算ロジック（純関数として切り出し、先にテストを書く）
3. ドットプロット描画（SVG推奨。棒グラフへの自動切り替えを含む）
4. 統計量カードと収束グラフ（セクション1完成）
5. **セクション3（F-6）** ← 教材としての価値が最も高い。ここを優先する
6. セクション2（A/B比較）
7. セクション4（実測データ入力）
8. 配色・文字サイズの調整、投影での可読性確認
