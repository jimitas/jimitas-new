## 背景と狙い

旧 jimitas.com の中で1つの大プロジェクトとして稼働していた「じみぷり」（算数プリント自動生成・印刷アプリ）を、Next.js 化された jimitas-new に統合した。

## 全体構成（採用したのは「案C」）

統合方式の検討:

| 案 | 内容 | 採用理由 |
|----|------|---------|
| 案A | 各プリントを独立アプリとして配置 | ❌ 39種は多すぎる |

## Phase 6: レイアウト忠実再現の苦戦

### 何が起きたか

39種すべてが React で生成・表示できるようになった段階で、印刷プレビューを移植元と並べてチェックしたところ、**見た目がかなり違う**ことが判明した。

主な問題:

| 症状 | 原因 |
|------|------|
| なんばんめ: □枠が長方形 | inline-block の高さがCSSで上書きされず | 
| なんばんめ: 動物が文字表示のまま | 移植元では画像（10種類） |
| なんじ: 時計が出ない | Canvas描画ロジックが未実装 |
| 印刷時にA4からはみ出す | `print zoom: 1.25` の負の遺産 |
| こたえの位置が固定されていない | 紙を折り曲げる教育設計が損なわれていた |
| 答えの段組が均等じゃない | 移植先で勝手に整列していた |
| 分数（１）（２）が1ページに収まらない | フォントサイズ判断ミス |

### 修正アプローチ

**「勝手に判断せず、移植元に忠実にしてください」** ── ユーザーからの強い指示。
「大きすぎるからといって少し小さくする」ような調整を勝手にやるな、という方針。

→ 1ファイルずつ移植元の CSS と HTML を grep で確認し、構造をそのまま再現する作業に切り替えた。

### 採用した固有の工夫

- **動物画像**: nanbanme アプリと共通のものを `next/image` で再利用
- **時計描画**: Canvas で `drawClock(ctx, hour, minute)` を実装（後にtokeiアプリと共通化）
- **印刷固定レイアウト**: `position: fixed` + `@page A4 portrait margin: 0mm`
- **答え位置の固定**: A4 下端に絶対配置（折り曲げて隠せる教育的配慮）
- **answerHtml**: 各プリント固有の答え表記が必要なものは生成関数が HTML を返す方式

## Phase 7: answerHtml スペーシング調整

### 問題

「①ひだりから5ばんめ②みぎから1ばんめ」のように **問番号と答えがくっついて読みにくい**。

移植元ではテンプレートリテラルで `${`①　${a}　②　${b}`}` のように全角スペース2つを挟んでいたが、
移植先で行ごとに改行を入れていたためレンダリング時に余分な空白が混入していた。

### 修正

文字列連結方式（`+` で連結）に統一し、改行を入れずに1行で書く。

```typescript
const answerHtml =
  `①　${a}　` +
  `②　${b}　` +
  `③　${c}` +
  `<br/>` +
  `④　${d}　…`
```

該当ファイル: nanbanme / hyouGraph / senMade / manMade / kasaNagasa / nanji1 / nanji2（全7ファイル）

## つまずきと学び

### 1. 「忠実に再現」の重み
`AI が良かれと思って勝手にレイアウトを調整する → 教育設計が壊れる` という事故。
移植元の作者は子どもの行動（紙を折り曲げる・答えを隠す）を観察して位置を決めている。
**「お行儀よく整えるな、現状を保て」** が新しいルールになった。

### 2. answerHtml は文字列連結
テンプレートリテラル + 改行 = 余計な空白。1問の答えを書くときは + で連結する。

### 3. 共通化できるものは積極的に
- 時計描画 → `src/lib/clockDrawing.ts` に抽出
- 動物画像 → nanbanme アプリと共通の画像
- BANGOU `["①","②",...]` → constants.ts に集約（リファクタリング段階）

### 4. 印刷レイアウトは独自世界
通常のレスポンシブと同居せず、`@page` + `position: fixed` で完全固定が正解。
過去の `print zoom 1.25` は印刷不能の地雷だったので削除。
