## 1. 5アプリへの localStorage 自動保存

### 対象アプリと保存対象

| アプリ | 保存対象 | 注意点 |
|---|---|---|
| 作戦ボード（sakusen-board） | `positions`, `isRotated` | リセットボタンを新規追加 |
| 漢字テスト作成（kanji-test） | フォーム入力一式 + `displayLines` | 既存のテキストファイル保存とは別物 |
| さんすうノート（sansu-note） | `items`（配置物）のみ | 手書きCanvasは対象外（容量・undo整合性のため） |
| 日本の都道府県（nihon-todouhuken） | `placed`/`results`/`cardOrder`/`locked`/`allCorrect` | 復元できたら自動シャッフルをスキップ |
| マスぬり（masu-nuri） | `mode`/`color`/`cellColors`/`hLineColors`/`vLineColors`/`strokes` | 「てがきだけけす」にも確認ダイアログを追加 |

### 採用パターン（fushi-dukuri を踏襲）

```tsx
const STORAGE_KEY = "jimitas_<app>_v1"  // 構造変更時はバージョン上げる
type SavedData = { ... }

const [loaded, setLoaded] = useState(false)

// マウント時に1回だけ復元
useEffect(() => {
  try {
    const raw = localStorage.getItem(STORAGE_KEY)
    if (raw) { /* バリデーションしてから setX */ }
  } catch { /* 破損データは無視 */ }
  finally { setLoaded(true) }
}, [])

// 編集時に毎回保存（loaded前は書き戻ししない）
useEffect(() => {
  if (!loaded) return
  try { localStorage.setItem(STORAGE_KEY, JSON.stringify(data)) }
  catch { /* 容量超過などは無視 */ }
}, [loaded, ...deps])

// リセットボタンで removeItem
```

### 設計判断のポイント

#### 自動保存 vs 手動保存
**自動保存を採用**。理由：
- 「児童が開いたときに続きから再開」という要件 → 保存忘れが起きないこと優先
- 失敗作も保存されるが、リセットで消せるので問題なし

#### Vercelデプロイの影響
影響なし。localStorage はブラウザ側の永続化、デプロイはサーバー側の更新。完全に独立。

#### コインシステムとの兼ね合い
コインも localStorage 保存だが、キーが別なので干渉しない。将来 Supabase 移行時は **localStorage → DB の引き継ぎ処理** が必要（コイン・状態の両方）。

#### `react-hooks/set-state-in-effect` lint エラー対応
nihon-todouhuken で発生（cardOrder の自動シャッフルがあるため）。既存パターンに合わせて `queueMicrotask` で囲んで解決：

```tsx
useEffect(() => {
  let parsed: SavedData | null = null
  try { /* parse */ } catch {}
  queueMicrotask(() => {
    /* setX をまとめて呼ぶ */
    setStorageLoaded(true)
  })
}, [])
```

#### バリデーションの徹底
`localStorage` のデータは破損したり、後からアプリ側のロジックが変わって整合しなくなったりするので、**読み込み時に必ず型・範囲チェック**：

```tsx
if (typeof data.tempo === "number" && data.tempo >= MIN_TEMPO && data.tempo <= MAX_TEMPO) {
  setTempo(data.tempo)
}
```

### 副次変更

マスぬりの「てがきだけけす」ボタンを `BtnConfirm` に置換し、確認ダイアログを挟むようにした（誤タップによる消失防止）。

## 2. 作戦ボードのマウスドラッグ修正

### 症状

タブレット（タッチ）では問題なし。PCマウスで速く動かすと、ピースが指/カーソルから置き去りになる。

### 原因の段階的特定

#### 第1段階：実装方式の確認
最初はライブラリ依存（react-moveable など）かと思ったが、調査の結果：
- **作戦ボード**：自作 Pointer Events（`react-draggable` が React 19 非対応のため）
- **さんすうノート**：自作 Pointer Events + ゴースト要素
- **recorder-play**：唯一 react-moveable を使用（穴の位置調整モード）

#### 第2段階：さんすうノートとの差分比較
両方とも自作 Pointer Events なのに、さんすうノートはマウスでも問題なし。決定的な違い：

| | さんすうノート（OK） | 作戦ボード（NG） |
|---|---|---|
| リスナーの貼り付け先 | `document.addEventListener("pointermove", ..., { passive: false })` | `<div onPointerMove={...}>` |
| pointer capture | 使わない | `setPointerCapture` 使用 |
| `preventDefault()` | 効く（passive: false） | React 合成イベントで効かない |

→ **document レベルリスナー方式に統一**することにした。

#### 第3段階：書き換え後も追従しない
document リスナーに変えたところ、追従はするが「ドラッグ中は要素が消えて、ドロップ瞬間にカーソル上に出現」する別の不具合が発生。

原因：`PlayerCircle` と `ArrowPiece` が `SakusenBoardPage` 関数の**内部で定義**されていた。

```tsx
// ❌ 問題コード（修正前）
function SakusenBoardPage() {
  const PlayerCircle = ({ num, team }) => { ... }  // 毎レンダーで新リファレンス
  const ArrowPiece = ({ type, uid }) => ( ... )
  ...
}
```

`setDraggingId` が呼ばれると親が再レンダー → React は「新しい型のコンポーネント」と判定して DOM を再マウント → `dragInfo.current.el` に保存していたのは**古い（unmount済み）DOM要素** → DOM 直接更新が画面に反映されない。

### 修正内容（3点セット）

```tsx
// ✅ 1. document レベルリスナー（passive: false で preventDefault 効く）
useEffect(() => {
  const handleMove = (e: PointerEvent) => {
    const drag = dragInfo.current
    if (!drag) return
    e.preventDefault()
    drag.el.style.transform = `translate(${x}px, ${y}px)`
  }
  document.addEventListener("pointermove", handleMove, { passive: false })
  document.addEventListener("pointerup", handleUp)
  document.addEventListener("pointercancel", handleUp)  // 取りこぼし防止
  return () => { /* removeEventListener */ }
}, [])

// ✅ 2. コンポーネントは関数の外で定義
function PlayerCircle({ num, team, pieceProps, rotationStyle }: Props) { ... }
function ArrowPiece({ type, pieceProps }: Props) { ... }
function SakusenBoardPage() {
  return <PlayerCircle pieceProps={pieceProps(id)} ... />
}

// ✅ 3. style に userSelect: 'none' を追加（保険）
style: {
  touchAction: "none",            // タッチ用
  userSelect: "none",             // マウス用
  WebkitUserSelect: "none",       // Safari 対策
  ...
}
```

### 副次変更

ドロップ時の効果音を `move2` から `pi` に変更。さんすうノートと統一して認知的負荷を下げる。

### セキュリティ確認（ユーザー懸念への回答）

document レベルリスナーは **dnd-kit, react-dnd, framer-motion** など主要ライブラリも採用する標準パターン。XSS リスク・権限昇格・情報漏洩いずれもなし。`useEffect` の cleanup で removeEventListener しているのでメモリリークもない。

## 教訓・メモリ追加

### `feedback_freedrag_implementation.md`（新規追加）

自由配置DnD（任意座標へドラッグできる形式）の3原則：

1. **document レベルでリスナーを貼る**（`{ passive: false }` 付き）
2. **ピースコンポーネントは関数の外で定義する**（再マウント回避）
3. **`userSelect: 'none'` を style に入れる**（保険）

既存の `feedback_drag_dom_direct.md`（PointerMove中はsetStateせずDOM直接）の補完。

### 設計上の暗黙ルール（再確認）

- **`setPointerCapture` はマウスでは破られやすい**。タッチでは安定しても過信しない。
- **インライン定義のコンポーネント + DOM ref 持ちのドラッグ**は致命的に相性が悪い。
