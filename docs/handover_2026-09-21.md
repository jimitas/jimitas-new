## この日いちばん効いた進め方

### 「1か所に書いた固定文字列を全ケースで使い回す」を疑う

今日見つかった不具合のうち**3件が同じ型**だった。

| どこ | 何が起きていたか |
|---|---|
| 解説の見出し | `"どうやって並べる？"` が固定文字列 → **探索**でも並べると出る |
| 矢印の凡例 | `"範囲の左はし（合体のときは…）"` → **合体しない**アルゴリズムにも出る |
| 写すステップの矢印 | `right` が `hi` と `q` の二役 → 凡例がそのステップだけ嘘になる |

但し書きを足すのはその場では最短の修正に見えるが、**文は全ケースに配られる**。
足したくなったら場合分けが要るサイン。ケース側から差しかえる口を作る
（`AlgoDef.pointerHelp` がその形）。

### 画面の文言は `_lib/` に置く

このプロジェクトの jest は `testEnvironment: "node"` で **React を描画できない**。
つまり**コンポーネントの中に書かれた文字列は原理的にテストで固定できない**。
今日見つかった2件がどちらもコンポーネント内の固定文字列だったのは偶然ではない。

`POINTER_HELP` と `howTitle()` を `_lib/describe.ts` へ出した。以後も同じ判断でよい。

### コード例は「貼って走らせて」確かめられる

マージソートのコード例を書きかえたあと、**JavaScript のコード例をそのまま
スクラッチパッドに貼り付けて 2008 ケース走らせ**、すべて昇順に並ぶことを確認した。
コード例は「人が読むだけのもの」になりがちだが、JS なら実行して検証できる。
（Python はこの環境に処理系が無い。スライス代入が等価であることで担保した）

### 実機を見なければ3件とも見つからなかった

`**` の表示・探索の見出し・凡例の3件は、**型もlintもテストも通っていた**。
文言を直したら必ずブラウザで見ること。

## 踏み直しやすい落とし穴

- **画面の文言をコンポーネントに直書きしない。** jest が node 環境なので固定できない
- **CSS を編集したら dev サーバーを再起動する**（`.next` を消してから）
- **RAF はタブが裏だと止まる。** ブラウザ自動操作で再生ボタンを押しても最後まで
  進まない。コマ送り（← →）で確かめる
- **ブラウザ自動操作では、ボタンにフォーカスが残っていると ← → が効かない。**
  `page.tsx` のキーハンドラが INPUT / BUTTON 等を除外しているため。
  余白をクリックしてから押す
- **Tailwind は生成CSSの順で勝敗が決まる。** `Btn` の `text-sm` は `text-base` では
  上書きできない（`text-[1rem]` なら勝つ）。font-size を足すときは `leading-6` もセットで
- **`@theme` に無い濃度は無言で効かない。** `danger` は -700 まで。`neutral` はトークンではない
- **並行チャットのときは、先に push してから次のチャットを始める。**
  同じリポジトリを2セッションが同時に触ると競合する
