## Part 1: cursor + 効果音の一貫性

### 課題

> 「クリックできるところでマウスホバー時に指マーク（cursor）を表示してほしい。
> 一貫性がなく、表示されるところとされないところがある。」
>
> 「モード切替や色の指定など、ナビ的なボタン操作にも分かりやすい効果音(pi/set)を統一してほしい。」

### 分類ルール

- **小さな移動・クリック** → `pi.mp3`
- **モード切替・色切替** → `set.mp3`

### 実装方針

ボタン共通部品（BtnGray, BtnPrimary, BtnSubject 等）と CSS にデフォルト適用。
**個別アプリでは手書きしない**ことを徹底し、メモリにルール化。

→ メモリ: [feedback_cursor_and_se_consistency.md](../../../Users/nonaj/.claude/projects/C--claude-edu-apps-jimitas-new/memory/feedback_cursor_and_se_consistency.md)

## Part 2: 学年配置の整理

### 課題

「いつの間にか1つのアプリが複数学年に配置されているケースが増えている」

### 議論と判断

| 案 | 判断 |
|----|------|
| 全部の学年に出す | ❌ トップページが見渡せなくなる |
| **初出原則（最初に学習する学年だけ）** | ✅ **採用** |
| 例外: かけ算の筆算②（3〜5年） | ✅ 整数→小数×小数の連続学習に必要 |
| 例外: わり算の筆算（4〜5年） | ✅ 整数→小数の連続学習に必要 |

### 実装

- 例外を `feedback_multi_grade_links.md` メモリに明記
- リコーダー（運指）は3年生のみ表示（4〜6年から削除）→ b8caf0f / ec61185

## Part 3: カードの科目別色分け

### 採用したルール

| 科目 | 色 |
|------|----|
| 算数 | 青系統 |
| 国語 | 赤系統 |
| 音楽 | 紫系統 |
| 体育 | オレンジ |
| 英語 | 茶色系統 |
| その他ツール | 緑系統 |
| 中高向け（コッホ・バーンズリー） | 黒系統 |

### 並び順

各学年セクション内で **算数 → 国語 → 音楽 → その他** の順に並べる。

例外配置:
- メトロノーム = 音楽
- 作戦ボード = 体育
- バーンズリー / コッホ曲線 = 中高向け（黒系統）

## Part 4: カード説明文の見直し

### 課題

「カードの説明が見切れて読めない」

### 対応

1. カードレイアウトを「上詰め」にして1行目をそろえる
2. 説明文を **小学生にわかりやすい短い日本語** に書き直し（難しい漢字は使わない）
3. 今後のアプリも同じルールで書くようメモリに追加

## Part 5: 絵あわせ・なんでもトランプの動作不良

### 症状

- リンクを踏んでもトップページに戻される
- 画像が表示されない

### 原因と修正

| 症状 | 原因 | 修正 |
|------|------|------|
| トップに戻される | ブラウザキャッシュ（古いリダイレクト） | シークレットモードで確認 → キャッシュクリア |
| 画像が表示されない | `next/image fill` が機能しない | 通常の `<img>` タグに変更（9c0d111） |
| カードが横並びにならない | レイアウト崩れ | 10枚を1列に並べるよう絵カード幅を調整 |

### 学び

絵あわせは「左から何番目のカードをめくって」という指示型ゲームのため、**1列に並ぶことが本質**。
横幅に合わせてカード幅を動的調整する必要があった。

### 調査対象

### 経緯

→ **このチャットで配色まで全部やると焦点がぼやける**ため、

委譲後の成果は [配色リファクタリングレポート](./report_2026-04-26_配色リファクタリング.md) に記録済み。

## つまずきと学び

### 1. 並行作業の競合管理
複数チャットを同時進行（このチャット + ふしづくり開発 + 別途SEO対策）。
コミットがぶつからないよう「競合がないか確認してから push」を徹底。
→ メモリ: [feedback_multi_chat_workflow.md](../../../Users/nonaj/.claude/projects/C--claude-edu-apps-jimitas-new/memory/feedback_multi_chat_workflow.md)

### 2. 一貫性は部品レベルで担保する
個別アプリで「cursor を付ける/付けない」を判断させると、
作るたびに記憶が薄れる。**共通部品にデフォルト実装** + メモリで強制。

### 3. 多学年配置は「初出原則」に統一
雑多に配置すると全体俯瞰ができなくなる。
特例（かけ算の筆算②、わり算の筆算）はメモリに明記して保護。

### 4. 大きな課題は早めに別チャットへ分割
配色まで含めて1チャットでやると、context が溢れて品質が落ちる。
**「テーマがずれたら別チャット」** が正解。

### 5. 「読めない説明文」は実害がある
小学生が使うアプリで、漢字や見切れ文字は致命的。
リファクタリングのついでに小学生視点で全部書き直した。
