| `dark-after-question` | **ボタンのラベルが表記ゆれで見つからず、そもそも届いていない** |

### 条件つきの検査は「何本に届いたか」を数える

`if (…) return` で早期リターンする検査は、緑でも1本も届いていないことがある。
判定を一時的に `.toBe(-1)` に書きかえて走らせ、**赤くなった本数＝届いた本数**を数える。

実際、「こたえあわせ後」の検査は62本すべて緑なのに**5本しか届いていなかった**。
漢字の「答え合わせ」と「こたえ」を取りこぼし、**いちばん見たい筆算5本が
まるごと検査の外**にいた。広げ直して 5本 → 12本 になった。

### CSS は「実機を見る」まで終わりではない

`Block.module.css` の罫線を `currentColor` に寄せたら、白55%を重ねた木箱の中では
「明るい地に白い線」になって逆に消えた。**ダーク検査は緑のまま通った。**
スクリーンショットで気づいた。

→ **地の明るさがテーマで変わる面だけ `currentColor`。常に明るい面は黒固定。**

## 踏み直しやすい落とし穴

- **CSS を編集したら dev サーバーを再起動する**（`.next` を消してから）。
  古い CSS のまま判定されると、壊したのに通ってしまう
- **RAF はタブが裏だと止まる。** ブラウザ自動操作で再生ボタンを押しても最後まで進まない。
  コマ送り（← →）で確かめる
- **Tailwind は生成CSSの順で勝敗が決まる。** `Btn` の `text-sm` は `text-base` では
  上書きできない（`text-[1rem]` なら勝つ）。font-size を足すときは `leading-6` もセットで
- **`@theme` に無い濃度は無言で効かない。** `danger` は -700 まで。`neutral` はトークンではない
- **並行チャットのときは、先に push してから次のチャットを始める。**
  同じリポジトリを2セッションが同時に触ると競合する
