### 前提（決定済み・蒸し返さない）

| 用途 | 角丸 | 段階3での扱い |
|---|---|---|
| 汎用の操作ボタン | 8px（`rounded-lg`） | **移行対象・286個** |

**8px を選んだので、移行しても見た目は変わらないはず。**
だから「差分ゼロ」を要求しながら進められる。変わったら、それは事故か発見。

### 進め方

1. `npm run dev` を起動
2. `npm run layout-compare before`（`APPS` 環境変数で対象を絞れる）
3. **先にコードを変えずに `after` → `diff` を実行し、差分ゼロを確認する**
   ベースラインが揺れるなら、移行後の「差分ゼロ」は何も証明しない
4. アプリを数本ずつ移行する
5. `after` → `diff` で差分ゼロを確認
6. 差分が出たら、それが何かを説明できるまで進めない

**一度に全部やらない。** 段階2では、ラッパーを外しただけでスマホ幅のボタンが
潰れて2行になった（`shrink-0` で解決）。数本ずつなら原因の切り分けができる。

### 移行中に踏みやすい罠

- **`shrink-0` を外さない。** flex 行の中では `w-32` は上限でしかなく、
  日本語ラベルは文字単位で折り返せるので激しく潰れる。**スマホ幅でしか出ない**
- **Tailwind は「生成CSSの順」で勝敗が決まる。** 部品側から後で渡すクラスで
  共通側を打ち消せないことがある（`gap-0` で `gap-1` を消せなかった実例あり）
- **`@theme` に未定義の濃度は無言で効かない。** 存在しないトークンを書いても
  エラーにならず、色が付かないだけ
- 進捗の再測定は `npx tsx scripts/radius-survey.ts`（要 dev サーバー）
