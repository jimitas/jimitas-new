> **⚠ 2026-09-20 追記：「差分ゼロ」は成り立たない。**
>
> `Btn` は背景と同色の `border-2` を引いている
>（枠線ありのボタンと並んだときに高さが4pxずれないようにするため）。
> 枠線のない手書きボタンを寄せると、**幅も高さも +4px** 増える。
>
> ```
> 変更前  button"セット"  60.13 × 32
> 変更後  button"セット"  64.13 × 36   ← border-2 のぶん
> ```
>
> 色と角丸は一致する。`shadow-sm` / 押し込みアニメ / クリック音も足される。
>
> **判定基準はこう変える：**
> 「差分ゼロ」ではなく「**差分は枠線由来の ±4px と、それに伴う近隣要素の
> 4px ずれだけ**」。色・角丸・それ以外のずれが出たら、そこで止まる。
>
> この方針は 2026-09-20 にオーナーが決定（箱の大きさが全アプリで揃うことを取る）。

### 進め方

1. `npm run dev` を起動
2. `npm run layout-compare before`（`APPS` 環境変数で対象を絞れる）
3. **先にコードを変えずに `after` → `diff` を実行し、差分ゼロを確認する**
   ベースラインが揺れるなら、移行後の「差分ゼロ」は何も証明しない
4. アプリを数本ずつ移行する
5. `after` → `diff` で差分ゼロを確認
6. 差分が出たら、それが何かを説明できるまで進めない

**一度に全部やらない。** 段階2では、ラッパーを外しただけでスマホ幅のボタンが
潰れて2行になった（`shrink-0` で解決）。数本ずつなら原因の切り分けができる。

### ⚠ 2026-09-20 に実測で分かった罠（ここが最重要）

**`Btn` の `text-sm` は、className から素直には上書きできない。**

| className に書いたもの | 結果 |
|---|---|
| `text-base` | **負ける**（14px のまま。黙って小さくなる） |
| `md:text-base` | 勝つ（レスポンシブ指定。名前付き部品はこれを使っている） |
| `text-xl` | 勝つ |
| `text-[1rem]` | 勝つ（**任意値は確実。迷ったらこれ**） |

Tailwind は「クラスを書いた順」ではなく「生成CSSの順」で決まるため。
スケールの名前（`text-base` など）は勝ったり負けたりするので、
**元のボタンに font-size 指定が無い（＝16px を継承していた）場合は
`text-[1rem]` で明示すること。** `text-base` と書くと 14px になって
ボタンが縮むのに、コードを読んでも気づけない。

実例：`fushi-dukuri` の「▶ 再生」は 85.34px → `text-base` では 83.67px（縮んだ）
→ `text-[1rem]` で 88.9px（＝元の 85.34 ＋ 枠線 4px）に収まった。

### 移行の手順（1アプリぶん）

1. `grep -n "<button" -A 8 <page.tsx>` で手書きボタンを読む
2. **8px（`rounded-lg`）の汎用操作ボタンだけ**を選ぶ。
   12px のカード・0px のマス目・4px の小さい操作・`rounded-full` のピル・
   条件で色が変わるトグル（＝`BtnMode` の仕事）は対象外
3. 元の font-size を確認する。指定が無ければ `text-[1rem]` を足す
4. `<Btn color="..." onClick={...} className="<余白と文字サイズ>">` に置きかえる
5. `APPS=<app> npx tsx scripts/layout-compare.ts after` → `diff`
6. 差分が「枠線由来の±4px」と「それに伴う数px のずれ」だけか確かめる。
   **大きさが変わった要素の数が、移行したボタンの数と一致していること**

### 差分の読み方

`合計差分: 266件` のような大きな数字に驚かないこと。
ツールは「変更前のみ」「変更後のみ」を別々に数えるので、
1要素が動くと2件になる。中身を分けて見るとよい。

```
大きさが変わった: 2      ← 移行したボタンの数と一致していればよい
位置だけ動いた  : 131    ← 横4px・縦3px以内なら枠線の波及
```

### 移行中に踏みやすい罠

- **`shrink-0` を外さない。** flex 行の中では `w-32` は上限でしかなく、
  日本語ラベルは文字単位で折り返せるので激しく潰れる。**スマホ幅でしか出ない**
- **Tailwind は「生成CSSの順」で勝敗が決まる。** 部品側から後で渡すクラスで
  共通側を打ち消せないことがある（`gap-0` で `gap-1` を消せなかった実例あり）
- **`@theme` に未定義の濃度は無言で効かない。** 存在しないトークンを書いても
  エラーにならず、色が付かないだけ
- 進捗の再測定は `npx tsx scripts/radius-survey.ts`（要 dev サーバー）
