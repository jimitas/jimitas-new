# 06 配色設計

> jimitas-new の配色ルール・トークン体系・スタイル系統をまとめた設計書。
> 全アプリで配色トーンを統一し、トップページからアプリ内まで一貫した「やわらかい・親しみやすい」印象を保つための原則を定める。

---

## 設計の3原則

### 原則1: UD配慮（赤緑色覚異常への対応）

- 赤緑色覚異常の方でも識別しやすい色を採用する
- **生の `red-*` は使わない**。リセット・停止系には rose 寄りの `danger` トークンを使う
- 色だけでなく「位置」「ラベル」「アイコン」も併用して識別性を確保する

### 原則2: ブランド = 色名ではなく「トーン」の統一

「ブランドカラー」とは緑1色のことではない。**ロゴと同じくらい柔らかいトーンに、すべての色を揃える**ことを指す。

- 緑（brand）も青（accent）もオレンジ（warm）も赤（danger）も、**同じ柔らかさで使う**
- 原色っぽい `bg-blue-500` `bg-red-500` `bg-purple-500` は禁止
- 「学校＝黒板＝緑」のような硬い印象ではなく、**ロゴの -400 トーン**を基準にする

### 原則3: 役割で色を分ける（ただし数色まで）

ボタンの役割が一目で分かるよう、**5つの役割色**を使い分ける。

| 役割 | トークン | 用途例 |
|---|---|---|
| 開始・確定 | **brand**（緑）| もんだい・セット・スタート |
| 判定・入力・変化 | **accent**（青）| こたえあわせ・数字・シャッフル |
| ヒント・補助 | **warm**（オレンジ）| こたえをみる |
| **リセット・停止・破壊** | **danger**（赤系・新設）| リセット・ストップ・全消去 |
| 行/列識別（特殊用途）| **rose**（ピンク）| 九九アプリの行ラベル |

## カラートークン

`src/app/globals.css` の `@theme` で定義する。Tailwind クラスとして `bg-brand-400` `text-accent-600` のように使う。

| トークン | 系統 | -400（基準）| -500（ホバー）| -600（アクティブ）| 用途 |
|---|---|---|---|---|---|
| `brand` | 緑 | `#34d399` | `#059669` | `#047857` | 開始・確定 |
| `accent` | 青 | （要追加 #60a5fa）| `#3b82f6` | `#2563eb` | 判定・入力 |
| `warm` | オレンジ | `#fb923c` | `#f97316` | `#ea580c` | ヒント・補助 |
| **`danger`** | 赤系（rose 同値）| `#fb7185` | `#f43f5e` | `#e11d48` | **リセット・停止**（NEW）|
| `rose` | ピンク | `#fb7185` | `#f43f5e` | `#e11d48` | 九九専用（変更なし）|

### danger トークンの追加方針

`danger` は **rose の値エイリアス**として新設する：

```css
/* globals.css への追加 */
@theme {
  /* ===== danger（リセット・停止・破壊的アクション）=====
     現状は rose と同値。後で「やはりオレンジに戻したい」と思ったら
     ここの値だけ書き換えれば全アプリのリセットボタンが一気に変わる */
  --color-danger-50:  #fff1f2;
  --color-danger-100: #ffe4e6;
  --color-danger-200: #fecdd3;
  --color-danger-300: #fda4af;
  --color-danger-400: #fb7185;
  --color-danger-500: #f43f5e;
  --color-danger-600: #e11d48;
  --color-danger-700: #be123c;
}
```

**意図**: `rose` は九九の「行・段識別」という意味色として残し、リセット用途とは名前で分離する。後で配色変更したいときは `--color-danger-*` の値だけ書き換える。

### accent-400 の追加が必要

現状 accent には `-400` トークンが定義されていない。基本スタイル「-400 ベースの白抜き」のために追加する：

```css
--color-accent-400: #60a5fa;  /* Tailwind 標準値 */
--color-accent-300: #93c5fd;  /* 同上 */
```

## 基本ボタンスタイル：「-400 ベースの白抜き」

**ボタンは原則「-400 単色背景 + 白文字」で統一する。** ホバーで `-500` に少し濃く、アクティブで `-600` までグラデーションする。

```tsx
// 基本パターン（brand の例）
className="bg-brand-400 hover:bg-brand-500 active:bg-brand-600
           text-white font-bold
           px-4 py-2 rounded-lg shadow-sm
           active:translate-y-0.5 transition-colors"
```

| 色 | 通常時 | ホバー | アクティブ |
|---|---|---|---|
| brand | `bg-brand-400` | `hover:bg-brand-500` | `active:bg-brand-600` |
| accent | `bg-accent-400` | `hover:bg-accent-500` | `active:bg-accent-600` |
| warm | `bg-warm-400` | `hover:bg-warm-500` | `active:bg-warm-600` |
| danger | `bg-danger-400` | `hover:bg-danger-500` | `active:bg-danger-600` |

### なぜ -400 ベースなのか

- **トップページのトーンと一致**: セクション下線 `border-brand-400`、カード左端の教科色も -400 系
- **柔らかいが識別性は高い**: -500 単色は「原色っぽさ」「教材っぽさ」が出るが、-400 は柔らかい
- **白文字とのコントラストも十分**: WCAG 基準を満たす

### 廃止するパターン

以下の従来パターンは**今後の新規実装では使わない**：

- ❌「白背景＋色枠＋色文字＋ホバーで -500 単色化」（旧 BtnQuestion 系の柔らか系）
- ❌「-500 単色背景＋白文字」（tashi-hissan 系の強い系）

既存の共通ボタン部品（BtnQuestion / BtnSet / BtnCheck / BtnShowAnswer / BtnUndo / BtnNum / BtnShuffle / BtnStart / BtnStop / BtnMode）は**段階的に「-400 ベースの白抜き」に書き換える**。

## 共通ボタン部品とトークンの対応

`src/components/parts/buttons/` の各部品が使うべきトークン（書き換え後）。

| 部品 | 用途 | 役割色 | 形状 |
|---|---|---|---|
| `BtnQuestion` | もんだい | brand | -400 白抜き |
| `BtnSet` | セット | brand | -400 白抜き |
| `BtnStart` | スタート | brand | -400 白抜き（既存と同方向）|
| `BtnCheck` | こたえあわせ | accent | -400 白抜き |
| `BtnNum` | 数字 0〜9 | accent | -400 白抜き |
| `BtnShuffle` | シャッフル | accent | -400 白抜き |
| `BtnShowAnswer` | こたえをみる | warm | -400 白抜き |
| `BtnStop` | ストップ | **danger** | -400 白抜き |
| `BtnUndo` | もどす（軽いリセット）| **danger** | -400 白抜き |
| `BtnConfirm` | 確認バー付きボタン | `color` prop で指定 | -400 白抜き |
| `BtnMode<T>` | モード切替トグル | brand（アクティブ -500、非アクティブ枠 -300）| 例外（トグル形式）|
| `BtnColor` | 色選択 | カスタム | 例外（色プレビュー）|

### 注意点

- **BtnUndo と BtnStop は danger に変更**（従来は brand / warm）
- **BtnMode はトグル形式の特殊ケース**として「アクティブ -500・非アクティブ -300 枠」を維持
- **新アプリで「もんだい」「こたえあわせ」「シャッフル」等を作るときは必ず共通部品を使う**

## モード切替・難易度切替の統一

### `<button>` 式トグル → `BtnMode` を必須化

```tsx
<BtnMode value="easy"   current={mode} onChange={setMode}>やさしい</BtnMode>
<BtnMode value="normal" current={mode} onChange={setMode}>ふつう</BtnMode>
<BtnMode value="hard"   current={mode} onChange={setMode}>むずかしい</BtnMode>
```

- 自前で `<button className="bg-blue-500 ..."` のように書くのは禁止
- 現状 `BtnMode` を使っていないアプリ（**suuzu-block, sangenshoku, gakuten** など）は段階的に置き換える

### `<select>` 式プルダウン → `border-brand-500` で統一

```tsx
<select className="text-center font-bold m-2 p-2 min-w-24 text-base md:text-xl
                   border-brand-500 text-black dark:text-gray-100 dark:bg-gray-700
                   border-2 rounded-lg shadow-lg">
  {ITEMS.map(item => <option key={item} value={item}>{item}</option>)}
</select>
```

- すでに `tashizan-1` / `hikizan-1` / `kazoeyou` で採用済み
- 他アプリの `<select>` も同じ書式に揃える

## 「物の色」として raw color を許容する場面

**ボタン以外の「物・概念・教科の識別」には Tailwind 標準色（pink/yellow/blue 等）を使ってよい**。
ただし「**意図をコメントで残す**」ことを必須とする。

| 場所 | 用途 | 色 | 理由 |
|---|---|---|---|
| **トップページ：カード左端** | 教科識別 | 算数=blue-400・国語=red-400・音楽=purple-400 等10色 | 教科を色で見分けるための意味色 |
| **トップページ：じみぷりバナー** | じみぷりの存在強調 | green-50→emerald-50・green-200・green-300 | 当面 raw のまま許容（将来 brand トークン化を検討）|
| `kazoe-bou` | 位の識別 | 百=pink・十=yellow・一=blue | 位を色で判別できる学習補助 |
| `kuku-array` / `kuku-yomi` | 行×列の識別 | 行=rose・列=accent・積=brand | UD配慮の九九色分け |
| `sakusen-board` | チーム識別 | 赤=`#DC2626`・青=`#1D4ED8` | 野外視認性・UD標準 |
| `okane` | 硬貨の見た目 | yellow / amber | お金の色イメージ |
| `sangenshoku` | 三原色学習 | RGB / CMY 各色 | アプリの題材そのもの |

**判断基準**: その色が**「ボタンの色」か「物の色」か**を区別する。物の色は raw OK・ただしコメントで意図を残す。

## アンチパターン（やってはいけないこと）

### ❌ ボタンに raw color を使う

```tsx
// NG
<button className="bg-red-500 hover:bg-red-600 text-white">リセット</button>
<button className="bg-blue-500 text-white border-blue-500">モード1</button>
<button className="bg-purple-500 ...">しゅうちゅう</button>

// OK
<BtnUndo handleEvent={reset} />
<BtnMode value="m1" current={mode} onChange={setMode}>モード1</BtnMode>
```

### ❌ -500 単色背景の「強い系」を新規実装で使う

過去のアプリ（tashi-hissan / hiki-hissan / kake-hissan-1 など）には残っているが、**新規実装では -400 ベースに統一**する。既存も段階的に書き換える。

### ❌ ホバーで色が大きく変わる「柔らか系」を新規実装で使う

旧 BtnQuestion 系の「白背景→ホバーで brand-500 単色化」は廃止方向。新規実装では「-400 白抜き → ホバーで -500」を採用する。

### ❌ 「ぶろっく方式」と「たし算筆算方式」を1アプリ内で混在

ぶろっくは「白背景＋色枠（柔らか系）」、たし算筆算は「単色背景＋白文字（強い系）」と方式が異なる。**新標準である「-400 ベースの白抜き」に揃えれば、この問題は自動的に解消する**。

## 新アプリ追加時のチェックリスト

新しいアプリを追加するときは以下を順に確認する。

- [ ] ボタンは共通部品（BtnQuestion/BtnSet/BtnCheck/BtnNum/BtnShowAnswer/BtnUndo/BtnShuffle/BtnStart/BtnStop）を使っているか
- [ ] モード切替は `BtnMode` を使っているか（自前 `<button>` で書いていないか）
- [ ] 難易度プルダウンは `<select className="border-brand-500 ...">` の書式に揃っているか
- [ ] リセット・停止系は `danger` トークン（`bg-danger-400`）を使っているか
- [ ] `bg-red-*` `bg-blue-*` `bg-green-*` `bg-yellow-*` `bg-purple-*` などの raw color をボタンに使っていないか
- [ ] raw color を使っている場合、それは「物の色」（位識別・教科識別・教材題材など）として正当化できるか
- [ ] `-500` 単色背景や「ホバー切替型」を新規で書いていないか（**-400 白抜き**になっているか）
- [ ] 1つのアプリ内で複数のボタンスタイルが混在していないか

## 段階的移行計画（既存アプリの書き換え）

新標準への移行は一気にやらず、以下の順で段階的に進める：

1. **Phase 0（即実施）**: globals.css に `--color-danger-*` と `--color-accent-300/400` を追加
2. **Phase 1**: 共通ボタン部品（BtnQuestion / BtnSet / BtnCheck / BtnShowAnswer / BtnNum / BtnUndo / BtnStart / BtnStop / BtnShuffle）を「-400 白抜き」に書き換え → 全アプリに自動反映
3. **Phase 2**: BtnConfirm に `color` prop を追加し、各アプリの `buttonClassName` 上書きを除去
4. **Phase 3**: ぶろっく等の自前 `<button>` 式モード切替を `BtnMode` に置き換え
5. **Phase 4**: 各アプリの `<select>` の枠線を `border-brand-500` に統一
6. **Phase 5**: tashi-hissan / hiki-hissan / kake-hissan-1 のインライン書き「クリア」ボタン等を `danger` トークン化
7. **Phase 6**: じみぷりバナーの raw green を brand トークンに置き換え（任意・将来）
